## Concurrencia estructurada

- `concurrent { ... }` crea un scope léxico de tareas.
- `spawn llamada(...)` crea un hijo poseído por ese scope.
- `await tarea`, `await tarea as outcome` y `await [a, b] as race` hacen
  explícitos los joins, fallos recuperables y carreras.
- Canales acotados, cancelación cooperativa, diagnósticos y límites del runtime
  evitan trabajo detached o sin límite.

Consulta [Concurrencia e I/O del Host](/es/docs/language/concurrency-and-io/)
para el contrato del lenguaje y el CLI.

## Autoridad explícita del host

Las operaciones de archivo y TCP usan recursos con propietario. Los programas
no reciben acceso ambiental para leer, escribir, conectar o escuchar. La
autoridad se otorga con flags exactos del CLI o los settings equivalentes de
`achronyme.toml`:

```bash
ach --allow-read ./data --allow-connect 127.0.0.1:443 run app.ach
```

Los efectos del host se rechazan dentro de código `prove` y `circuit`. El
compilador mantiene el mundo externo fuera del límite determinista de prueba.

## Ejecución nativa

`ach run` soporta el intérprete y LLVM 21 ORC JIT con el selector explícito
`--engine interpreter|jit|auto`. `ach aot` emite un ejecutable nativo contra el
runtime AOT empaquetado. El CI de release cubre fallback al intérprete, JIT,
AOT, layouts instalados, límites de recursos y paquetes Linux x86_64/aarch64.

## Confianza de proving fail-closed

La generación de pruebas ya no crea llaves locales de forma implícita:

```bash
# Solo desarrollo. El resultado no es confiable para producción.
ach --insecure-dev-setup run proof.ach

# Ruta de producción. El store debe coincidir con el circuito optimizado exacto.
ach --trusted-key-dir ./trusted-keys run proof.ach
```

Los stores BN254 Groth16 de producción ligan la proving key al R1CS, transcript
de fase 1, contribuidores de fase 2, beacon público final y evidencia del
release. La verificación Groth16 separada para BN254 y BLS12-381 está disponible
mediante `ach verify`. La generación Plonkish y BLS12-381 sigue siendo solo para
desarrollo en esta línea.

Consulta [Generación de Pruebas](/es/docs/zk-concepts/proof-generation/) para
los comandos de usuario y la guía versionada de trusted setup del repositorio
core para el workflow completo del operador.

## Release del editor

El editor `0.3.0` sigue la revisión final del core y agrega
resaltado sintáctico y semántico para concurrencia estructurada, task handles,
I/O con propietario y builtins conscientes de capacidades. También incluye
activación del lenguaje Circom, diagnósticos respaldados por el parser, hover,
completion, símbolos de documento, definiciones, referencias y rename.
